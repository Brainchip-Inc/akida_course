What is BrainChip Akida 2, and why does it exist?

Before writing a single line of code, we need to understand the fundamental problem Akida solves — and why solving it required rethinking how chips process AI at the edge.

~25 min read Conceptual — no code required 4 interactive diagrams
01 · The Problem

AI at the edge has a power problem

Edge AI means running inference locally on a device — a camera, a wearable, an industrial sensor — without sending data to the cloud. This sounds simple. But it runs straight into a hard constraint: edge devices are battery-powered, fan-less, and physically small.

Traditional AI accelerators — the GPUs and NPUs that power cloud inference — are designed for throughput, not efficiency. They consume watts to tens of watts. Running one on a wrist-worn sensor would drain the battery in minutes. Running one always-on, processing a live microphone or camera stream 24 hours a day, is simply not viable.

But raw power numbers only tell part of the story. The deeper issue is architectural — traditional accelerators are built around a fundamentally wasteful assumption.

02 · The Core Insight

The wasteful assumption: process everything, always

A conventional neural network accelerator treats every inference identically: every layer runs, every weight multiplies every activation, every cycle — regardless of whether the computation matters.

Akida's insight is different: not every value the network computes is worth propagating. As a network processes an input, most of the intermediate activations — the values inside the network, after each layer — turn out to be zero. This is true whether the input is a static corridor or a busy, ever-changing scene; it's a property of how well-trained sparse networks represent information, not a property of how "eventful" the raw input is. Akida is built to detect those zeros as they're produced and skip the computation they would have triggered. Nothing is skipped because the scene didn't change — computation is skipped because a value inside the network turned out to be zero.

This means Akida's efficiency gains aren't limited to "boring" inputs like idle security cameras. Any workload where the network naturally produces sparse activations — which, done right, is most of them — benefits.

Dense vs event-driven compute — same reduction regardless of input content
Toggle between modes. Unlike an event camera skipping quiet frames, this reduction doesn't depend on the input changing — it's the same whether the input is static or constantly changing, because it comes from zeros inside the network, not from motion in the raw signal.

This is the neuromorphic insight: only propagate what's non-zero. Instead of running every layer every cycle regardless of what it computes, BrainChip Akida detects the zeros a network produces internally and skips the computation they would have triggered — on every input, busy or idle alike.

03 · Sparsity

Sparsity — where the zeros come from, and which ones matter

Sparsity means a large fraction of the data being processed is zero, and anything multiplied by zero is zero — so that computation can be skipped. Akida is architected around exploiting this, primarily in one place: activation sparsity. After each layer, a sparsity-inducing activation (e.g. ReLU, or sparsity-regularized variants) sets many values to zero. Those zeros are exactly what Akida's event-driven compute fabric skips — this is the core mechanism, not a side effect.

Activation sparsity — the core mechanism

In a well-trained sparse network, 50–90% of activations are zero after each layer and need not propagate further. Akida's hardware fires only on the non-zero events, so the skipped computation translates directly into skipped power draw.

Two other forms of sparsity are worth knowing about, but they play a smaller or different role on this hardware:

Weight sparsity

Comes in two flavors that matter very differently for Akida. Unstructured pruning (zeroing individual small weights scattered throughout a tensor) shrinks model size but doesn't speed up inference — the hardware isn't built to skip individual zeroed weights, so the dense compute still happens. Structured pruning (removing entire channels, filters, or neurons) is different: it actually shrinks the architecture — fewer channels to compute, period — so it produces a smaller, faster model on Akida the same way it would on any accelerator.

△ Structured pruning's speedup isn't from Akida's event-driven mechanism — it's the ordinary "smaller model → less compute" effect. Combine it with activation sparsity and the gains stack: one shrinks the model, the other skips computation inside the smaller model that remains.

Input sparsity

Matters a great deal if you're using an event-based sensor upstream of Akida — a static background produces zero events. But it isn't inherent to Akida itself: Akida works fine on conventional dense-frame input too, deriving its efficiency from what happens to that data once it enters the network.

Why this matters for hardware design: A chip purpose-built for sparse data doesn't check each value and skip it — that itself costs power. Akida's architecture fires only on events. Sparsity is structural, not an afterthought bolted onto a dense accelerator. This is what makes the efficiency gains real rather than theoretical.

04 · Architecture

At-memory compute — the other half of the efficiency equation

Even with sparsity eliminating most of the arithmetic, there is still a second fundamental bottleneck: memory bandwidth. Moving data between a compute unit and external memory (DRAM) is enormously expensive in energy — often consuming more power than the actual computation itself. This is called the memory wall.

The memory wall — where energy is spent in a traditional accelerator vs Akida
In Akida, each neural processing engine has dedicated SRAM sitting next to it. Weights are loaded once at startup and stay there — data travels micrometers, not centimeters to external chips.

BrainChip's solution, built into every Akida 2 core: distribute both compute and memory together. Each neural processing engine has its own dedicated on-chip SRAM sitting right next to it. Weights are loaded once and stay resident. In most deployments, no external DRAM is needed at all — the entire model lives on-chip. This is a massive win for both power and latency.

05 · Design Philosophy

Fully digital and quantized — what that means in practice

Some neuromorphic chips use analog circuits, which can be smaller and more efficient but vary with temperature and manufacturing tolerances. BrainChip Akida takes a deliberately different path: it is fully digital. Everything operates on integers — no floating-point units anywhere in the signal path.

Weights and activations are stored and computed as low-bitwidth integers. This integer-only architecture has four important consequences for you as a developer:

Predictable, repeatable results

Integer arithmetic is exact. No analog variation, no temperature drift. The same model produces identical outputs on every chip, every time.

Standard process compatibility

Akida synthesizes on any standard digital CMOS process. Customers integrate it into their own SoCs on whatever foundry they already use.

Small, efficient MACs

An 8-bit integer multiply uses roughly 20× less energy than a 32-bit float multiply, and occupies a fraction of the silicon area.

Quantization is mandatory

Any model must be quantized before it can run on Akida — converted from float32 to integer. The MetaTF and MetaONNX toolchains automate this step.

⚠

Akida 1.0 vs Akida 2.0 — a critical difference: The original Akida (AKD1000) supports 1, 2, and 4-bit weights only. Akida 2.0 drops 1-bit and instead supports 4-bit and 8-bit. This matters because the MetaONNX SDK (onnx2akida) defaults to 8-bit quantization. If you target older AKD1000 hardware, you must use the MetaTF / QuantizeML path and explicitly target 4-bit or lower. This course focuses on Akida 2.0.

06 · Product Family

Where Akida 2 sits in the product family

BrainChip offers Akida as a licensable IP core — semiconductor companies integrate it into their own chips. There are several configurations targeting different power and performance points:

Product Generation Bitwidths Primary target Power
Akida Pico 2.0 8-bit Always-on wake-word, vital signs < 1 mW
AKD1000 1.0 1 – 4-bit Edge inference, image classification, audio ~150–440 mW
Akida 2.0 IP ★ 2.0 4, 8-bit Vision, video, TENNs — this course ~300 mW typical

★ This course targets the Akida 2.0 IP — specifically the 6-node configuration represented by the SixNodesIPv2 virtual device in the SDK, and the FPGA evaluation board when available.

A note on TENNs support: "TENNs" isn't a single, uniform capability across the product line. The Akida 2.0 IP covered in this course supports the buffered variant (TNP_B — think of it as a temporal convolution that can be made recurrent). The state-space-style recurrent variant (TNP_R) is available on Akida Pico only. Keep these two apart when discussing TENNs support.

The one-sentence summary

BrainChip Akida 2 is a fully digital, integer-only, event-based neuromorphic AI accelerator IP that achieves milliwatt-level power by processing only non-zero activations, storing model weights in on-chip SRAM adjacent to the compute, and firing computation only when meaningful input events occur.
