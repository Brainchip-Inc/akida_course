Building your first model for Akida

The two toolchains, the rules your model has to follow, and where to run it, in ten minutes.

Akida only spends compute on the lit cells: non-zero activations. Everything in this talk is about getting your model into that shape.

About 1.5 minutes

Why Akida cares how you build the model

Zeros cost nothing

Akida is event-driven: it only computes on non-zero activations. After a ReLU, a well-trained network often has 50 to 90% of its activations at zero, and those multiply-accumulates are skipped entirely.

More sparsity means lower latency and less energy per inference.

Weights live on the chip

Each neural processor has its own SRAM. Weights are loaded once when the model is mapped and stay there, so a model that fits on chip never pays for trips to external memory.

That makes model size and bit width a hardware decision, not just an accuracy one.

Design for sparse activations and an on-chip footprint, and the hardware rewards you.

About 1.5 minutes

Rules your model has to follow

Use supported layers

Conv2D, depthwise conv and Dense are the core. Dilated and grouped convolutions aren’t supported. When unsure, start from zoo building blocks.

Prefer ReLU

ReLU is what creates the zeros Akida skips. GELU or Swish give up sparsity, so use them only when you need them.

Channels last

Inputs are (H, W, C). Keras is already channels-last. MetaONNX handles the PyTorch layout for you.

Feed uint8

The hardware takes uint8, 0 to 255. Cast your preprocessed input explicitly; float input raises an error.

Keep the first layer at 8 bits

The input layer is the most sensitive to quantization. 8-bit in, 4-bit elsewhere is a good default.

Don’t skip QAT at 4 bits

Post-training quantization alone usually costs accuracy at 4 bits. A few epochs of QAT recovers most of it.

Keras example, step 3 of 10

Build an Akida-friendly model

Conv, BatchNorm, ReLU blocks throughout. BatchNorm is folded away and ReLU is absorbed into each layer.

Watch out: SeparableConv2D fails to convert. Write it as a depthwise conv plus a 1×1 conv, each followed by ReLU.

Global average pooling before the Dense layer keeps the classifier small enough to run on chip.

model = keras.Sequential([
  keras.layers.Rescaling(1/255, input_shape=(28, 28, 1)),
  keras.layers.Conv2D(32, 3, strides=2),
  keras.layers.BatchNormalization(),
  keras.layers.ReLU(),
  keras.layers.DepthwiseConv2D(3, strides=2, padding="same"),
  keras.layers.BatchNormalization(),
  keras.layers.ReLU(),
  keras.layers.Conv2D(64, 1),
  keras.layers.BatchNormalization(),
  keras.layers.ReLU(),
  keras.layers.GlobalAveragePooling2D(),
  keras.layers.Dense(10),
], name="mnistnet")

Keras example, step 5 of 10

Quantize to 4 bits

Post-training quantization with real training images as calibration data. That matters more for accuracy than any other setting.

The first layer stays at 8 bits; everything else goes to 4. The result is still a Keras model, so you can evaluate and train it.

Expect a small accuracy drop here.

qp = QuantizationParams(input_weight_bits=8,
                        weight_bits=4,
                        activation_bits=4)

qmodel = quantize(model, qparams=qp,
                  samples=x_train,
                  num_samples=1024, batch_size=100)

qmodel.compile(optimizer=keras.optimizers.Adam(1e-4),
               loss=loss, metrics=["accuracy"])
qmodel.evaluate(x_test, y_test)  # compare to float

PyTorch and ONNX example, step 3 of 8

Build the model in PyTorch

A depthwise conv in PyTorch is Conv2d with groups equal to the channel count. AdaptiveAvgPool2d(1) exports as global average pooling.

Keep scaling inside the model. Multiplying by 1/255 in forward() lets the deployed model take uint8 pixels directly.

class MnistNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(1, 32, 3, stride=2),
            nn.BatchNorm2d(32), nn.ReLU(),
            nn.Conv2d(32, 32, 3, stride=2, padding=1, groups=32),
            nn.BatchNorm2d(32), nn.ReLU(),
            nn.Conv2d(32, 64, 1),
            nn.BatchNorm2d(64), nn.ReLU(),
            nn.AdaptiveAvgPool2d(1), nn.Flatten())
        self.fc = nn.Linear(64, 10)

    def forward(self, x):           # x: 0..255
        return self.fc(self.features(x * (1 / 255)))

PyTorch and ONNX example

What’s different from the Keras path

No QAT step

MetaONNX does 8-bit post-training quantization only. If accuracy drops, improve calibration data or the model, or move to MetaTF for 4-bit with QAT.

Calibrate with float samples

Calibration runs the original float graph, so samples must match its input type. Keep 1/255 scaling inside the model.

Hardware needed sooner

You can convert, read the report and check mapping anywhere. Generating and running the inference model needs a physical device or Akida Cloud.

Watch the boundaries

Ops Akida can’t run fall back to CPU. Each Akida-to-CPU handoff shows up in the report with its size in KB; keep them few and small.

Sparsity-aware training

Make more zeros on purpose

Akida skips every zero activation, so sparsity is free speed and energy. A plain ReLU network gets some for nothing. Adding a penalty on activations during training pushes it much further, at a cost in accuracy you get to choose.

  1. Measure the baseline sparsity
  2. Add a penalty on ReLU outputs
  3. Train and sweep the strength
  4. Quantize, fine-tune and convert as usual
  5. Measure on Akida and pick a setting

Builds on the Keras digit classifier from the first example. Tested with akida 2.19.3 and akida_models’ compute_sparsity.

Sparsity-aware training, step 2 of 5

Add a penalty on ReLU outputs

An L1 penalty on each ReLU’s output pushes small activations to exactly zero. In Keras it’s one argument: activity_regularizer.

Pick the strength carefully. The penalty sums over every activation in the map, so big early layers feel it most. Start around 1e-5 to 1e-4.

def build(l1=0.0):
    reg = keras.regularizers.L1(l1) if l1 else None
    return keras.Sequential([
      keras.layers.Rescaling(1/255, input_shape=(28, 28, 1)),
      keras.layers.Conv2D(32, 3, strides=2),
      keras.layers.BatchNormalization(),
      keras.layers.ReLU(activity_regularizer=reg),
      keras.layers.DepthwiseConv2D(3, strides=2, padding="same"),
      keras.layers.BatchNormalization(),
      keras.layers.ReLU(activity_regularizer=reg),
      keras.layers.Conv2D(64, 1),
      keras.layers.BatchNormalization(),
      keras.layers.ReLU(activity_regularizer=reg),
      keras.layers.GlobalAveragePooling2D(),
      keras.layers.Dense(10)])

Sparsity-aware training, step 3 of 5

Train and sweep the strength

There’s no universal setting, so train a few strengths and record accuracy and sparsity for each.

Training is the same as before. Keras adds the penalty to the loss automatically.

Too strong kills the network. At 1e-3 every activation went to zero and accuracy fell to chance.

results = {}
for l1 in [0, 3e-5, 1e-4, 3e-4]:
    m = build(l1)
    m.compile(optimizer="adam", loss=loss,
              metrics=["accuracy"])
    m.fit(x_train, y_train, epochs=10,
          validation_split=0.1)
    acc = m.evaluate(x_test, y_test)[1]
    sp = compute_sparsity(m, samples=x_test,
                          batch_size=1000)

Getting more out of it

Target the big layers

Early layers have the largest activation maps, so their zeros save the most work. Use a stronger penalty there and a lighter one deeper in.

Fine-tune, don’t start over

Starting from a trained model and adding the penalty for a few epochs at a low learning rate usually costs less accuracy than training with it from scratch.

Try scale-invariant penalties

L1 also shrinks activations that stay non-zero. Hoyer-style penalties (L1 over L2) target sparsity itself and are less sensitive to scale.

Trust the Akida number

Float sparsity is a proxy. Measure on the converted model, then confirm the latency and energy gain on hardware or Akida Cloud.
